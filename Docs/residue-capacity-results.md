# 残留物与生态容量：固定矩阵实验结果

日期：2026-10-27。任务 002，未修改产品规则。

## 结论

数据支持“尸体和污渍计入容量，并压低本场景可获得的繁殖空间”。R1 中，初始 26 或 30 个残留物的两类共 20 个单元，均保持 8 个活体、0 次产卵、0 次孵化；10、20 个残留物的产卵量也在每个种子中低于各自 0 残留对照。

“残留越多，卵就越容易孵不出”没有得到单调剂量反应支持。R1 的 26、30 剂量组根本没有卵，不能称作孵化失败；0 剂量组有 3/5 种子出现成熟卵滞留，10 剂量组有 1/5，20 剂量组没有。尸体和污渍两类在相同种子、剂量下，除残留物类别计数外，表内指标逐项相同；两组 0 剂量是重复对照，不能当成十个独立样本。

R2 中，定时清尸体的五个种子都出现更多产卵、孵化和更高的终点活体数；但成熟卵滞留不是逐种子都下降：19、42 的保留组为 0，清理组反而有短暂滞留。清理组的死亡总数也更高。数据不证明所有不购买清理工具的真实玩家必然停滞，也不将清理的所有差异归因于容量。

## 计划、方法与证据

[预先提交的计划](residue-capacity-plan.md) 的提交为 `a4bab2e`，早于本结果文件及证据文件。产品基线为 `f351d45`；固定种子 7、19、42、73、101，7200 秒、2 秒步长。60 个正式单元分别运行 Swift / C#，共 120 次正式模拟，所有世界、事件、分钟样本、新增计数观测与统计指标均通过双端比对。初始化及框架检查另列，不算正式单元。

R1 使用一个预置稳定巢穴、8 只成虫和固定的每 60 秒供食安排。对同一种子，各剂量使用相同成虫、PRNG 位置和 serial 的初始快照，避免不同数量残留物的初始化抽样消耗干扰剂量对比。两组 0 剂量的完整确定性输出在五个种子下均相同。

R2 保留 F 原场景输入，仅替换固定种子；清理组再增加 `removeCorpsesEvery: 60`。清理在 t=60、120、…、7140 发送原有 remove 信号，事件时间为下一步的 t+2；不清除污渍或活体，也不绕过保护规则。remove 会增加 interactions，后续随机分支可能改变，因此它是完整干预对照，不能隔离为纯容量效应。

[原始证据 JSON](residue-capacity-evidence.json) 包含全部 60 单元、每单元双端原始指标、计数序列、事件分类计数、终点阶段分布，以及输入、源文件和确定性输出哈希。计数序列按连续相同状态无损压缩，保留首末观测时间；完整输入和双端输出可由脚本重建到 `build/simulation/residue/`。JSON 中未提交非确定性耗时，哈希也排除 elapsedMs。

表中“成熟卵·秒”为每步后尚为 egg 且 age≥180 的数量乘以 2 秒后累计；“滞留秒”为至少一枚这样的卵存在时的累计秒数。右端点刚达到成熟的本步也计时。首达≥32 是初态和完整步后的总数门槛；初态超过门槛为 0，从未达到为 -1。产卵和孵化按卵壳事件计数，births 包含新卵和孵出的幼体；初始残留不计 deaths。巢穴、死亡、总数均取终点。

## 推测核对与局限

- 尸体、污渍计入总容量：代码核对支持，R1 在统一初态下的产卵减少和高剂量零产卵也支持；两种残留的主指标一致。
- “不清理会压低后续繁殖空间”：本场景数据支持。不能把高残留组的 0 次孵化当成已有卵孵化失败，因为这些单元根本没有产卵。
- “已有卵也孵不出”：本次在部分单元确有 age≥180 仍为 egg 的累计时长；但并非所有种子都有，0 残留也有，剂量反应不单调。R2 的清理组仍能发生短暂滞留。
- “尸体只能用吸尘器清除”：不完整。双端全局扫描在喷雾解锁后也能清除未受保护尸体；污渍不在扫描清除范围。工具价格是解锁成本，不是每次使用费用。
- 任务背景的 F “20 尸体 + 14 活体”对应已有 1.7.1 证据中 seed 42 的 `control`。本次当前默认 `treatment` 的 seed 42 保留组是 **18 尸体 + 18 活体 = 36**，没有终点卵，成熟卵滞留为 0；不能把历史 control 数值当作本次复现预期。
- R1 人为提供稳定巢穴与食物，使用共同随机数位置的快照；它衡量这些受控条件下的容量现象，不代表自然游玩频率。R2 的 remove 信号影响 interactions 和后续随机分支，因此出生、死亡或滞留的差值不能全部解释成“释放容量”。
- 观测分辨率为 2 秒，首次达到 32 使用初态及步后观测，不捕捉单步内短暂峰值。实验没有 UI、真人游玩、付费选择或工具解锁过程，不给产品处理方案。
