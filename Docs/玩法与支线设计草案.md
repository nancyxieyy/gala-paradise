# 旮旯乐园：玩法、支线与成就设计草案

记录日期：2026-09-10  
状态：讨论记录，供下一步开发评审使用。本次只新增此文档，不修改游戏代码、存档或测试包。

本文整合用户提出的多动物养成／驱赶支线、成就卡，以及此前讨论的五种玩法。下文的触发次数、关系门槛、奖励与容量均为设计建议，不代表已确认的最终数值，也不代表已开发功能。正式开发前按本文件中的待定项再确定参数。

## 1. 核心体验与范围

电脑是一处有角落、食物、藏身处和住客的生活空间。玩家通过日常行为影响谁愿意留下来、谁会躲避自己，以及动物之间如何相处。支线自然浮现，不要求开局选阵营，也不要求每条线全部触发。

玩家可以喜欢蟑螂，收养几只熟悉的旮杂；也可以不喜欢蟑螂，结识老鼠和猫，让它们帮忙驱赶；还可以混合游玩，保护自己的旮杂、让其他动物巡逻外围。

整合的内容：

1. 会“偷藏”用户主动交付内容的收纳助手。
2. 记住对待方式、形成个体经历与关系的动物。
3. 痕迹、巢穴、稀有访客组成的桌面探索。
4. 与住客约定安静时间的专注挑战。
5. 朋友间主动领养、交换住客。
6. 旮杂养成、老鼠巡逻、猫咪守护与多物种共居支线。
7. 记录初次体验、阶段行为和关系里程碑的成就卡。

不纳入本轮方案：真实杀毒、自动删除文件、自动清缓存、卸载残留机制。文件夹闲置可以影响游戏栖息倾向，但不等于真实文件是垃圾或不安全。小狗与更多物种保留为未来扩展，当前只设计旮杂、老鼠和猫。

## 2. 用一套状态连接所有玩法

### 2.1 个体、物种与环境分开记录

| 层次 | 记录内容 | 用途 |
| --- | --- | --- |
| 动物个体 | 唯一身份、物种、外观、姓名、关系阶段、信任、警惕、经历、是否受保护 | 同一只动物记住玩家，并产生专属反应 |
| 物种发现 | 是否初遇、相关互动与支线是否可出现 | 发现老鼠不等于驯养老鼠；看到猫爪也不等于已与猫熟悉 |
| 栖息地 | 游戏内食物、痕迹、窝、旮杂活跃度、安全区、巡逻区 | 影响出现地点和场景，不对真实文件作风险判断 |
| 玩家记录 | 专注、主动收纳、捕获、击败、领养与关系里程碑 | 驱动成就、内容解锁和收藏 |
| 场景调度 | 当前场景、冷却、安静模式、保护规则 | 防止多个系统同时争抢一个角色或打断办公 |

信任与警惕不是同一条数值的正负端。动物可以认得你，同时仍有些怕你。单次误操作不抹除长期关系；长期离线也不造成死亡或关系归零。

### 2.2 关系阶段

陌生访客 → 认得玩家 → 熟悉来访 → 可建立伙伴关系 → 伙伴／常驻住客。

- 初遇由游玩时长、生态事件或探索触发；具体时长待平衡，不把当前内测的分钟数当成正式值。
- 熟悉依赖跨多次来访的有效互动，不靠连续点几十下瞬间刷满。
- 达到门槛后出现自然邀请，例如旮杂不走了、老鼠留下小物件；由玩家确认成为伙伴。
- 命名与伙伴关系相互独立：可以先给熟悉访客取名。命名后也纳入保护，避免已产生感情的个体被误杀。
- 猫的个体身份通过爪色、花纹和来访记录体现，不需要露出完整身体。
- 伙伴数量设有限槽位（数值待定）；达到上限时暂停新邀请，不覆盖已有伙伴。

### 2.3 互动必须表达清楚意图

增加明确的“互动／抚摸／投喂”入口，与捏取、拖鞋等工具分开。选择“捏一下”不能同时算作抚摸。点老鼠或猫时，伤害工具只产生安全反馈，不触发伤害。

有效互动指对象可见、允许交互、动作完成且不在奖励冷却内。快速重复点击可以有轻反馈，但不重复增加信任或发奖励。

## 3. 五种玩法怎样接入支线

### 3.1 偷藏与收纳：用户交给它，它帮忙藏好

触发链：熟悉动物 → 展示抱纸条的小场景 → 玩家主动交付第一段文字／链接／待办 → 动物搬回窝 → 收纳入口解锁。

- “偷”是表演，只接收玩家明确拖入或提交的内容；不主动读取剪贴板、不移动或隐藏真实文件。
- 最初范围为文字、链接、待办。动物窝里的纸条是收纳记录的表现，不占用真实文件夹。
- 从首次交付起提供稳定的清单入口，可查看、复制、取回、删除。动物离开、躲藏、被驱赶、暂停或关系变化，都不能让内容无法取回。
- 取回后是否继续保留、完成待办还是仅复制，由明确操作决定；不得把复制算作删除。
- 可保管内容来自玩家的明确交付，不在桌面气泡公开展示正文；成就分享也不包含这些内容。
- 旮杂可抱纸条、老鼠可拖小袋子；任一熟悉动物都能解锁基础收纳，不强迫讨厌蟑螂的人先收养蟑螂。猫支线也能提供统一收纳入口，动物动画可延后制作。

交叉：窝里的装饰纸条来自收纳数量；专注可以关联一条主动选中的待办；动物被猫吓走时，收纳数据仍在清单中。

### 3.2 记忆与关系：反应有因果

触发链：投喂／抚摸／放过／追赶等事件 → 个体经历变化 → 下次来访出现相应动作 → 熟悉关系／支线邀请。

- 喂食并等待它吃完、成功抚摸、追赶后主动放过，分别产生不同记忆。
- 普通旮杂被追赶会躲鼠标、探头试探；经历多次逃脱后，可能戴小头盔出现。
- 只有活着逃脱的个体能记住被追赶。被击败后不能无说明复活并继承同一身份。
- 伙伴受到误触时逃回窝或暂时回避，不会永久死亡；后续友好互动可以恢复亲近。
- 场景可记录个性，但不读取打字内容、工作内容来推断情绪。是否接入闲置状态等设备信号另行评审。

交叉：关系使收纳、召回、巡逻和守护逐步可用；趣味经历可进入领养卡，私密使用信息不可进入。

### 3.3 痕迹探索：先看到生活留下的东西

触发链：满足生态条件 → 出现有限的脚印／碎屑／触角 → 玩家主动查看 → 找到窝、访客或普通资源 → 记录发现。

- 痕迹不自动算发现，必须展示出实际对象或完成探索事件。
- 猫来之前旮杂可先散开；老鼠经过后游戏面包屑减少；金色碎屑可引向黄金旮杂。
- 发现窝不必摧毁，可以喂食、观察、驱赶或设为允许栖息的位置。
- 安全区内不安排攻击任务；有名字的伙伴窝不会成为“必须清除”的目标。
- 即使关闭文件夹联动，也可以在虚拟桌面角落探索，不用权限解锁基本支线。
- 同屏痕迹有上限，过期自行淡出，错过可再出现，不用常在线才能补齐图鉴。

交叉：探索提供认识动物的机会，也连接黄金资源；猫鼠之间的动静解释角色出入，而非互不相关的随机动画。

### 3.4 专注约定：大家先安静一会儿

触发链：遇见任一物种并发现专注入口 → 玩家主动设定时长 → 动物收拾／回窝的简短开场 → 安静计时 → 完成后反馈。

- 专注功能不要求驯养某一物种，也不要求先购买道具。
- 默认期间没有随机出虫、探头、猫鼠追逐、文件夹爆发或成就弹窗。若提供盒缝探头等装饰，必须由玩家主动开启。
- 用户主动打开收纳仍可用，但不引发新的剧情；计时结束后仅安排一个简短庆祝场景。
- 专注时暂停随机生态场景，不在结束瞬间补发积压访客。关系不衰减。
- 专注计时独立于动物动画：隐藏桌宠不影响计时；用户暂停计时才停止。关闭应用、系统休眠或计时中断不自动算完成。
- 中途结束没有惩罚，不损失好感。专注是否给金壳及奖励上限待定，不能成为轻易刷资源的入口。

交叉：可选择收纳清单中的待办作为本次任务；完成计时与完成待办分开确认。

### 3.5 朋友领养：带着一段小故事入住

触发链：养出可分享住客 → 玩家选择分享 → 生成领养卡／码 → 朋友主动接收 → 入住并触发初遇场景。

建议首版采用“领养副本”，而非永久转让：发送方保留原住客，接收方获得新身份的住客，保留允许分享的外观、姓名与趣味经历，关系从新入住开始。后续如做真实转让，必须另定交付和撤回规则。

- 卡片只含主动选择的公开资料，不含路径、纸条、链接正文、真实办公记录。
- 收到领养动物立即开启该物种的发现记录，但巡逻、守护等能力仍要在本地培养；不继承发送方的金壳、工具、成就或伙伴信任。
- 接收方须主动接受；没有自动侵入朋友桌面或自动向朋友发消息。
- 相同领养凭证在同一存档只能领取一次，容量不足先收藏卡片，不覆盖住客。
- 领养动物到家即受保护，不因尚未建立本地伙伴关系而被击败。
- 码的离线／在线形式、防伪与跨设备身份尚待技术选型，不在本轮确定。

## 4. 支线触发与交叉

| 支线 | 开始条件 | 关键行为 | 阶段结果 | 可连接的玩法 |
| --- | --- | --- | --- | --- |
| 旮杂室友 | 见到普通旮杂 | 多次来访中投喂、友好互动、允许栖息 | 熟悉个体、命名、伙伴邀请、窝 | 收纳、经历、领养、专注 |
| 老鼠巡逻员 | 初遇老鼠 | 留食物、有效抚摸、重复友好来访 | 老鼠伙伴；玩家指定巡逻区 | 驱赶普通旮杂、探索痕迹、收纳 |
| 猫咪守护者 | 初遇猫爪 | 爪背互动、玩耍、重复来访 | 猫伙伴；玩家指定守护区或召唤 | 猫爪落地守候、普通旮杂退散 |
| 桌面侦探 | 看见一处可探索痕迹 | 查看、追踪、选择如何处理窝 | 新访客、稀有事件、发现卡 | 所有关系线、黄金资源 |
| 多物种共居 | 至少两种动物已熟悉，且玩家愿意设置区域 | 安全窝、错时巡逻、分开喂食 | 共居场景；动物互相熟悉 | 伙伴保护、共同专注、合影卡 |

各线并存、可晚点再走、没有永久阵营锁。赶过普通旮杂的玩家仍可养其中一只；喜欢旮杂的玩家也能结识猫。拒绝邀请只推迟相应内容，以后可重新触发。

### 4.1 动物间关系的边界

- 老鼠帮助驱赶是一种卡通游戏设定，不作为真实动物行为知识呈现。
- 巡逻与守护针对普通野生旮杂，以赶回角落为主，不自动杀死，不自动产金壳，也不计入玩家击败数。
- 猫可以偶尔拨弄普通旮杂、放跑目标；守护有效期间仍应保证该区域明显安静，不能让性格动画破坏功能反馈。
- 猫可能让陌生老鼠躲开；玩家自己的老鼠只暂时回窝，不丢失、不受伤。默认避免让猫与伙伴老鼠同时占用同一区域。
- 受保护住客（已命名、已成为伙伴、已领养）不被工具、扫描、猫鼠场景永久伤害。即使离开安全窝，保护仍随个体生效。
- 安全区保护区内所有旮杂；如果与巡逻区重叠，安全区优先，界面应清楚展示有效范围。
- 放弃常驻身份建议采用“送别”，而非解除保护后允许击杀；细节待定。

## 5. 统一触发逻辑：不让支线互相打架

每个场景都应有：前置条件、可用对象、区域、冷却、互斥标签、结果事件、可重复性、取消后的处理。

调度顺序：

1. 检查暂停／专注／安静设置；不合适的随机场景本次跳过，不能无限排队。
2. 应用个体保护和区域规则，排除不可攻击对象。
3. 优先处理玩家主动操作，例如取回纸条、抚摸、召回；它们可以取消普通闲逛。
4. 检查场景占用。一个动物同一时间只能有一个主动作，一个区域同一时间只演一个主要事件。
5. 条件仍满足才展示；实际动作成功结束后发出结果事件。
6. 统一结算个体经历、资源和成就，再进入冷却。重复事件不得重复结算。

互斥示例：

| 同时发生的请求 | 处理 |
| --- | --- |
| 猫要进场，老鼠正在递还纸条 | 先完成递还；猫延后或跳过，不打断内容取回 |
| 玩家抚摸旮杂，猫要巡逻 | 玩家交互优先；受保护个体始终不作为目标 |
| 启动专注时正有追逐 | 安全结束追逐并回窝，然后进入安静状态 |
| 清理窝时里面有收纳内容 | 只清理游戏痕迹；清单仍完整可取回 |
| 一个黄金目标同时被两个动作命中 | 第一条成功处理事件生效；后续忽略 |
| 出现金壳、初遇、命名等多个成就 | 统一收入卡册，轻提示一次，不连续弹窗 |
| 老鼠巡逻结束，马上又随机刷一群旮杂 | 巡逻区设安静冷却，随机刷新尊重区域状态 |

支线进度是历史记录，当前动物暂时隐藏不导致回退。屏幕显示预算优先保证少量角色和空白时间，伙伴常驻表示关系稳定，不代表永远占着屏幕。

## 6. 黄金卵壳与不同路线的公平性

黄金卵壳继续作为道具解锁资源。捏取等基础手段、抚摸、基础投喂、查看成就与专注入口不能要求先花金壳，避免循环锁。

建议黄金旮杂支持两种成功收获方式：击败／捕获后收获，或友好互动后完成一次自然脱壳收获。这样友好路线不用为购买工具伤害自己的住客。

- 一个黄金旮杂身份只提供一次金壳结算，不因躲藏、重启、命名或切换路线重复产出。
- 友好收获后的个体可以继续来访或培养，但不成为无限金壳来源。
- 金壳成功到账才算“首次黄金收获”；只看见黄金旮杂是另一个发现记录。
- 首版成就奖励建议以卡面、称号、窝装饰为主。若少量奖励金壳，必须设一次性结算并另行平衡。
- 领养住客、动物自动巡逻、反复抚摸不产出可无限循环的金壳。

## 7. 成就卡设计

### 7.1 表现与统计口径

成就卡包括名称、插画、触发说明、获得日期和可选动物姓名。默认没有好友排名，不因没走某一条线扣完成分。未触发支线可用模糊提示，避免一开始把惊喜全部剧透。

“击败”指玩家主动使未受保护的野生旮杂（含黄金变种）从活体进入死亡结果。有效捏／拍／喷可计数，击空、飞走、对尸体重复操作不计数。吸尘、友好收获、驱赶是独立事件，不硬算击杀。范围工具按真实被击败的唯一活体数量统计；后台扫描、伙伴巡逻不计入玩家主动击败成就。

用户提到的第一项按“击败第一只蟑螂”记录；名称与文案可改，首只／三只的里程碑保留。

### 7.3 避免成就扭曲玩法

- 不用“全成就”强迫喜欢动物的人走击杀线；按发现、关系、应对、生活等类别展示收藏。
- 不奖励伤害伙伴、反复改名、先喂后杀等刷取行为。
- 同一个结果可以解锁不同维度的卡，但每张卡只授予一次；例如首次黄金击败可以同时满足对应资源卡和有效击败统计。
- 领养可触发初遇和入住卡，但伙伴成就须在本地完成培养，不能直接继承发送方成果。
- 成就以实际结果为准：看到不等于养成、点下不等于摸到、派出不等于巡逻成功。
- 卡册可随时查看；分享由玩家主动操作，默认不带私人收纳内容或电脑路径。
- 旧存档只有可信的历史计数才补发。只有当前尸体不能推断历史击败数；已有伙伴／名字等未来新增字段也不能凭空生成。

## 8. 三种自洽的游玩过程

### 喜欢旮杂的玩家

投喂 → 同一只重复出现 → 熟悉并命名 → 伙伴与安全窝 → 交付纸条 → 友好收获黄金卵壳 → 专注约定 → 生成领养卡。全程可不击杀，仍有工具资源、实用入口和足够的成就。

### 不喜欢旮杂的玩家

手动应对普通旮杂 → 首只／三只成就 → 遇见并抚摸老鼠 → 培养巡逻伙伴 → 后续结识猫、设置守护区。可由老鼠或统一入口使用收纳；不需要先喜欢或收养蟑螂。

### 混合型玩家

养一只有名字的旮杂 → 给它留安全窝 → 结识猫或老鼠 → 外围巡逻，伙伴受保护 → 错时投喂和来访 → 触发共居。工具与自动驱赶都不会让已建立关系的旮杂永久消失。

## 9. 进入开发前的待定项

1. 信任成长、互动冷却、伙伴槽位、稀有来访频率与金壳数值。
2. 猫的有效抚摸范围、玩耍方式、召唤冷却；老鼠巡逻持续时间与覆盖区域。
3. 安全窝与巡逻区的交互方式，以及多屏幕下区域如何保存。
4. 领养码采用离线卡还是在线服务；当前建议副本领养，是否接受这一形式。
5. 收纳内容的容量、保存形式、导出／删除方式；与窗口动画彻底分离的数据保障。
6. 正式版是否保留当前内测的自动繁殖与频繁金色来访数值，哪些旧工具需要改为更清楚的命名。
7. 首批成就插画、卡名、装饰奖励；不在文档阶段承诺制作量或开发工期。

逻辑上的开发依赖仅作下次讨论参考：先统一个体身份、事件结算、保护规则与场景调度，再接关系／支线和成就；收纳、专注、领养接入同一套状态。本文记录的玩法全部保留，不代表要求下一版同时完成。
