# 产品决定

## 已定

- **D1（2026-10-27）路线**：按 0 → 3 的顺序推进。先打基础（协作与 CI → 代码可读性 → 修生态容量问题），再做「渐进式、让人想玩下去」的体验改进和新内容。
- **D2（2026-10-27）分工**：Claude 规划与审查，Codex 写代码，只通过仓库交流（流程见 `README.md`）。Claude 审查通过且 CI 全绿后，在 PR 里写明「可以合并」，**由你点合并**；如果你希望 Claude 直接合并，在这里写一句授权即可。
- **D3（2026-10-27）谁改代码**：所有具体代码改动（产品代码、测试、CI、脚本）都由 Codex 做。Claude 只写任务文件、审查意见、设计文档和 `.collab/` 下的协作文件；你把任务交给 Codex。
- **D4（2026-10-27）只用 GitHub**：代码只推送到 GitHub（`origin` = `github.com/nancyxieyy/gala-paradise`），不再推送到阿里云 Codeup。
- **D5（2026-10-28）残留物处理 = 方案 D**（原 Q1，数据见 `Docs/residue-capacity-results.md`）：尸体和污渍不占生态容量；尸体在原地慢慢风干，期间给所在位置增加少量食物，然后消失（「不收拾反而招来更多」）；污渍不影响生态，一直保留到被清洁剂擦掉。满员时成熟卵进入休眠，有空位再孵化。实现见任务 003。
- **D6（2026-10-28）不打扰原则：忙时疯长但藏着，闲时出来**（你的想法）。你忙的时候（电脑负载高、操作频繁），小住客在角落里繁衍得更快，但不出来打扰；等你闲下来，或者打开很久没碰的文件夹时，再陆续出来。具体怎么判断「忙」、出来的节奏，先写设计文档，确认后再拆任务。
- **D7（2026-10-28）长期支柱的顺序**（原 Q3）：第一批做「不打扰」(P1) + 「旮旯日报」(P2)，第二批做「遗传与进化」(P3)。「经营角落」(P4)、「收集与交换」(P5) 放后面。见 `Docs/design/long-term-pillars.md`。
- **D8（2026-10-28）「忙」的判断**：综合电脑负载（CPU / GPU）、距离上次操作的时长（不读按键内容）、前台是否全屏，不只看 GPU。
- **D9（2026-10-28）日报时机**：默认在「从忙转闲」时出现；设置里可以改为每天固定时间，或只在打开小窝时显示。
- **D10（2026-10-28）界面精简**（原 Q4）：主面板改为菜单栏 / 托盘小弹窗；新手只见「喂一点」和「勿扰」，工具、小窝等用到才出现；「歇一会儿」与「专注」合并为「勿扰」；纸条、专注计时器、安全窝、共居、巡逻、领养码分享从界面收起（保留数据），「撒点面包屑」删除；试玩文件夹移入设置的开发者区域。实现见任务 004。
