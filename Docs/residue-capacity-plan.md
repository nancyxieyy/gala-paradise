# 残留物与生态容量：预先固定的实验计划

日期：2026-10-27。任务 002；产品基线为 `f351d45`（任务 001 已合并）。本文先于实验实现和结果提交；不根据运行结果挑选种子、改变条件或选择报告范围。

## 问题和范围

核对尸体（`corpse`）、污渍（`stain`）是否计入总容量，以及在指定条件下是否伴随产卵减少、成熟卵滞留。只增加无界面模拟器的实验输入和观测，不修改任何产品代码、数值或随机数调用。

代码预核对表明：WorldBridge 确实同步所有非猫鼠住客；添加、产卵、孵化确实使用总 `creatures.count`。但“尸体只能用 6 金壳吸尘器清除”不完整：解锁 4 金壳喷雾后，全局扫描也会移除未受保护的尸体；污渍不在扫描清除范围。工具兑换是一次性解锁，不是每次清理付费。双端位置和其他核对写入任务的实现记录。

不评价 Q1 的处理方案，不推断所有真实玩家最终都会停滞。实验不包含桌面 UI、WorldBridge 的实际输入、受保护尸体、工具经济或猫鼠占用桌面名额的情形。

## 固定矩阵

所有正式运行使用种子 **7、19、42、73、101**，活跃时长 **7200 秒**，步长 **2 秒**、生长倍率 **1**，默认容量 **38**、默认 `treatment` 迁移规则。每个单元都跑 Swift 和 C#；合计 60 个单元、120 次正式模拟。所有五个种子逐项报告，不用均值替代个体结果。

### R1：初始残留物剂量反应

- 一个栖息地 `nest`，`food=1`、`nestability=0.9`、`nest=true`、`stable=120`，无初始药剂或扰动。预置巢穴是为了避免“随机未形成巢穴”掩盖容量门槛。
- 8 只成虫；其余个体仅为指定的残留物。残留量固定为 **0、10、20、26、30**；分别使用全 `corpse`、全 `stain`。初始总数为 8、18、28、34、38，不超过容量。
- 从 t=0 起每 60 秒发送 `food`，`amount=1`，不发送其他动作，不进行残留清理。这保证所有组采用同一供食安排，不把食物耗尽当成容量效应。
- 为避免“多放一个残留物就多消耗初始化随机数”混淆剂量对比，使用现有 `initial` 快照输入：对每个种子和残留类型，先用真实模拟器在 **0 秒**初始化 8 成虫 + 30 残留物；随后取前 8 成虫和前 N 个残留物组成各单元初态，保留同一个 `rng`、`serial` 和其余世界字段。成虫始终排在残留物前面。不是重写 PRNG 或调整个体属性，也不调用产品清理路径构造初态。
- 因此同一种子的十个单元具有相同成虫属性和实验开始时的随机数位置；后续规则分支不同导致随机数消耗不同属于实验结果。两组 0 残留单元应完全一致，作为初始化检查。

R1 共 **2 类型 × 5 剂量 × 5 种子 = 50 单元**。不额外补入卵；若高剂量组没有产卵、没有成熟卵滞留，也如实报告，不能把“没有卵”说成“卵孵不出”。

### R2：现有 F 场景对照

直接复制 `Tests/Simulation/scenarios/F-two-hours.json` 的条件，只按固定矩阵替换 seed。保留组没有新增清理字段；清理组唯一输入差异为 `removeCorpsesEvery: 60`。不改 F 原文件，也不将历史版本“20 尸体 + 14 活体”当成本次默认迁移规则的预定结果。

可选清理字段只在测试模拟器中生效：在相对 t=60、120、…、7140 秒、执行本步原有动作之前，按当前个体数组顺序，为当时所有 `corpse` 发送现有 `remove` 信号。不删除污渍、卵或活体，不跳过受保护规则；不补做 t=7200 的终点清理。模拟器在下一次 `step` 内处理信号，因此 t=60 发送的信号对应世界事件时间 62 秒，与现有动作的时间语义一致。未填写或非正间隔时不触发清理；非整步间隔按首次达到该时点的 2 秒边界处理，不在本次矩阵内使用。

`remove` 是原有玩家信号，会增加 `interactions`，可能连带影响访客与后续随机分支。R2 衡量的是整个“每 60 秒清尸体”干预的结果，不将差值全部归因为容量，也不把它当作产品实现建议。

R2 共 **2 组 × 5 种子 = 10 单元**。

## 预先固定的统计口径

每个正式单元报告以下原始数值，并保留双端一致性结果：

| 指标 | 定义 |
| --- | --- |
| 最终活体数 | 终点 `stage` 为 `adult` / `baby` / `gold` 的个体数；不含卵、尸体、污渍或访客 |
| 产卵次数 | 事件日志中 `trigger=fertility` 的事件数，按卵壳计数 |
| 孵化次数 | `trigger=incubation` 的事件数，按孵化卵壳计数；不是幼体数量 |
| births | World 原始计数，包括实验期间新建的卵和幼体；初始化 `record=false`，不计初始个体 |
| 首次达到 32 的时间 | 初态及每个完整模拟步后首次观察到总数 **≥32** 的世界时间；初态已经超过时为 0，从未达到时为 -1 |
| 成熟卵累计时长 | 每步后 `stage=egg && age>=180` 的数量 × 2 秒后求和，单位为 **卵·秒**；这是右端点采样口径，成熟阈值刚好达到的本步也计入 |
| 成熟卵滞留墙钟时长 | 同一采样口径下，只要有至少一个上述卵就累计 2 秒；不因同时存在多枚卵重复计时，单位为秒 |
| 巢穴、死亡数 | 终点 `nest=true` 的栖息地数及 World 原始 `deaths`；初始尸体不算本次死亡 |

另保留终点卵数、尸体数、污渍数、总个体数、实际移除尸体数，以及总数/活体/卵/成熟卵/尸体/污渍/巢穴的逐步计数。逐步计数只对连续相同的状态做无损游程压缩，每段保留首末观测时间，便于复算门槛时间和滞留积分。

这些计数是观测，不发送额外信号、不调用随机数、不改变 World。既有的世界、事件和分钟样本必须保持一致；新增观测独立放在输出的 `capacityEvidence` 中。

## 数据、复现与判读

场景文件和独立运行脚本放在 `Tests/Simulation/experiments/residue/`。脚本自己调用 `swiftc` 编译模拟器并构建 .NET 模拟器，**不 import `run`**。正式运行前先做初始化配对、清理时序和统计积分的框架检查；这些检查单列，不纳入 60 单元结果，也不据此调实验条件。

预定复现命令：

```sh
python3 Tests/Simulation/experiments/residue/residue.py
python3 Tests/Simulation/run.py
python3 Tests/Simulation/diff_base.py --base origin/main --require-identical
python3 Tests/style_check.py
```

`GALA_DOTNET` 可指定 .NET 可执行文件；未指定时查 PATH，再使用本地已有 `build/toolchain/dotnet/dotnet`。不下载或引入新的项目依赖。

每次运行的完整输入、双端输出留在 `build/simulation/residue/`。提交的 `Docs/residue-capacity-evidence.json` 包含固定矩阵、源文件哈希、每个单元的全部原始指标、压缩计数序列、事件分类计数及确定性输出哈希；Swift / C# 的状态、事件、样本和新增观测逐项比对，通过后只保留一份共同原始观测，数值字符串仅沿用现有双端比对的数值等价口径。耗时等非确定性字段不参与哈希。

结果写入新的 `Docs/residue-capacity-results.md`，逐项列出 50 个 R1 和 10 个 R2 单元，再给固定分组的汇总。只陈述是否支持推测、未观察到的现象与局限；既不挑种子，也不提出修改方案。两组 0 剂量重复、不发生孵化的单元和失败的假设全部报告。
